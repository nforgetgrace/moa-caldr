# v0.1.4 검증 · 2026-09-09

## 반영한 동작

- 위젯의 10sp 제목, 좌우 10dp·상하 8dp 여백, 최대 3개 제목과 별도 `+N`, 네이버 연보라·Google 초록색은 유지한다.
- Google 계정 목록은 넓은 선택 창과 우측 선택 표시를 사용한다. 이메일은 한 줄이며, 큰 글자에서 공간을 넘으면 말줄임한다. 접근성에는 전체 이메일을 제공한다.
- 일정 저장 위치에는 캘린더 이름을 한 번만 표시하고 서비스·계정을 보조 정보로 분리한다. 이름과 계정이 같은 `My Calendar · My Calendar` 중복을 없앴다. 동일한 이름의 서로 다른 캘린더는 ID와 계정으로 구분하여 유지한다.
- 선택 창은 서비스별 목록, 색상, 선택 표시, 스크롤, 고정된 닫기 버튼을 제공한다. 캘린더를 선택하거나 선택 창을 닫아도 작성 중인 내용은 유지한다. 기존 일정의 원본 계정은 변경할 수 없다.
- 기기 캘린더 목록과 일정 조회가 모두 성공한 결과만 함께 캐시한다. 조회 예외와 null Cursor는 성공한 빈 목록으로 취급하지 않는다. 마지막 정상 결과는 프로세스 종료 후에도 복원할 수 있도록 저장한다. 선택한 Google 계정 필터는 복원된 자료에도 적용한다.
- 캘린더 읽기 권한이 없어지면 기기 캐시를 제거한다. 정상 조회로 확인된 빈 결과와 삭제도 반영한다. 실패를 숨기거나 삭제된 일정을 영구 유지하지 않는다.
- 네이버와 기기 캐시의 조회 범위를 유지·확장하여, 더 좁은 백그라운드 조회가 이전에 받아 둔 기간을 지우지 않는다. 네이버는 누적 범위를 다시 조회한 뒤 검증한 결과를 한 번에 반영한다. 서버 통신 자체를 증분 프로토콜로 변경한 것은 아니다.
- CalDAV 목록의 일부 응답이 실패하면 전체 조회를 실패로 처리한다. 접근 실패를 캘린더 삭제로 해석해 기존 일정을 지우지 않는다.

## 검사 범위와 결과

전용 AVD `moa_calendar_api35`, API 35, `emulator-5554`에서 확인했다. Provider 계정·일정과 CalDAV 캐시는 모두 격리된 테스트 자료다. 실제 Google 또는 네이버 계정으로 인증한 검사는 아니다.

화면 검사는 실제 스크린샷을 검토한 것이며 모든 프레임의 영상 분석이나 픽셀 일치 검사는 아니다. UI 테스트에서 재사용된 접근성 노드의 이전 텍스트를 읽는 문제가 있어, API 34 이상에서 [UiAutomation.clearCache](https://developer.android.com/reference/android/app/UiAutomation#clearCache())로 새 접근성 트리를 읽도록 테스트 실행기를 보강했다. 실제 화면의 변경은 실패 당시 캡처에서도 확인했고, 수정한 실행기로 전체 시나리오를 다시 통과했다.

검사 종료 후 테스트 Provider 캘린더와 일정, 주입한 캐시, 테스트 APK를 제거하고 글자 크기와 화면 방향을 복원했다. 연결 전의 빈 화면도 다시 확인했다.

## 빌드 증거

- versionName **0.1.4**, versionCode **5**.
- `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest` 성공.
- 단위 테스트 **76개**, 실패·오류·건너뜀 **0**.
- Android lint 오류 **0**, 경고 **30**. 기존 버전/스타일/속성 호환 권고와 SharedPreferences KTX 사용 권고가 남아 있다.
- 설치 가능한 개발용 APK: `dist/moa-calendar-0.1.4-debug.apk`. 서명 검증과 에뮬레이터 설치 성공.
- 검사 로그·테스트 집계·서명·SHA-256: `verification/v0.1.4/`.
- 검토 화면: `screenshots/v0.1.4/`.

회귀 검사는 인증 정보가 없는 전용 에뮬레이터에서만 실행한다. 각 시나리오는 원래 캐시를 복원하며, 실행기는 앱 APK에 포함되지 않는다.

```sh
adb -s DEVICE_SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
adb -s DEVICE_SERIAL install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s DEVICE_SERIAL shell am instrument -w -e scenario background com.moa.calendar.test/com.moa.calendar.RefreshRegressionRunner
# scenario: manual / widget / changes
# widget 검사는 홈 화면에 모아 월간 위젯이 있어야 한다.
```

Android 설정의 **강제 중지**는 별도 동작이다. API 35에서 강제 중지 후 위젯이 비활성화되고, 앱을 직접 열면 복구되는 것을 확인했다. 이는 [Android 15의 위젯·PendingIntent 정책](https://developer.android.com/about/versions/15/behavior-changes-all#stopped-state)이다. 일반적인 백그라운드 프로세스 종료 검사는 `am kill`로 따로 수행했다.

## 남은 출시 검증

Galaxy 실기기의 Samsung 런처, 실제 계정의 Google/Naver 왕복, 절전·재부팅·장시간 백그라운드 동기화, 대규모 계정 및 모든 화면 크기는 이번 환경에서 검증하지 않았다. 이전에 받아 오지 않은 기간의 오프라인 자료, 서버가 실제로 빈 응답을 보낸 경우까지 화면 유지를 보장할 수는 없다. 누적 조회 범위가 큰 계정의 성능과 응답 크기도 실계정 검증 대상이다. 배포용 서명과 스토어 출시는 수행하지 않았다. 이 결과는 확인한 범위의 품질 개선과 회귀 검증이며, 모든 기기·모든 상황에 대한 상용 품질 인증은 아니다.
