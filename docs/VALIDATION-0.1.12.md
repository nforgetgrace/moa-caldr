# v0.1.12 — 위젯 새로고침 스피너와 최근 동기화 시각

월·다가오는 일정 위젯의 새로고침 버튼을 누르면 버튼 자리에 스피너가 바로 나타나고 상태줄이 "동기화 중…"으로 바뀝니다. 즉시 실행되는 동기화 잡이 끝나면 성공·실패와 관계없이 스피너가 사라지고, 성공했으면 상태줄에 `최근 동기화 M/d HH:mm`을 작게 표시합니다. 표시 시각은 마지막으로 성공한 동기화 잡과 네이버 서버 확인 시각 중 더 최근 값입니다. 동기화 잡이 응답하지 않으면 90초 뒤 다음 갱신에서 스피너를 내립니다.

월 위젯 헤더는 `‹ 9월 ›`를 가운데에 두고, 오른쪽 새로고침 옆에 Gook's 표시를 둡니다. 왼쪽에 같은 폭의 빈 자리를 두어 월이 정중앙에 옵니다.

## 검증 범위

- 단위 테스트(`WidgetRefreshTest`): 진행 중 판정과 90초 만료, 날짜·시간 형식과 시간대, 상태줄 우선순위(동기화 중 > 오류 > 캘린더 없음 > 최근 동기화 > 저장된 일정).
- 격리 에뮬레이터(`widget_refresh` 시나리오): 실제 홈 화면 위젯에서 새로고침 탭 → 스피너와 "동기화 중" 즉시 표시 → 잡 완료 후 `최근 동기화 M/d HH:mm` 표시와 새로고침 버튼 복귀, 저장값 확인, 오래된 진행 플래그 만료.
- 기존 `widget_month`, `widget`, `calendar_colors` 시나리오를 새 레이아웃으로 재실행했습니다.
- APK 메타데이터·서명·SHA-256, 단위 테스트·lint 집계는 `docs/verification/v0.1.12/`에 기록합니다.

## 확인 한계

에뮬레이터에는 네이버 계정이 없어 동기화 잡은 기기 캘린더 조회만 수행합니다. 실제 네이버 동기화 중 스피너 지속 시간은 서버 응답에 따릅니다. 앱 안에서 실행한 수동 동기화는 네이버 확인 시각을 통해서만 위젯 상태줄에 반영됩니다.

## 구현 근거

- [RemoteViews](https://developer.android.com/reference/android/widget/RemoteViews): `ProgressBar`는 위젯에서 허용되는 뷰이며, `partiallyUpdateAppWidget`으로 가시성만 즉시 바꿀 수 있습니다.
- [JobScheduler](https://developer.android.com/reference/android/app/job/JobScheduler): 기존 즉시 실행 동기화 잡(마감 0)의 완료 시점에 스피너를 해제합니다.
