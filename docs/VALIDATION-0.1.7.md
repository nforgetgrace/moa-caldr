# v0.1.7 검증 · 2026-09-10

## 변경

기존에는 날짜별 목록을 눌러 편집할 수 있었지만 월·주 달력의 일정 막대는 날짜 선택만 했고, 편집 화면도 ‘일정 상세’로 표시되어 수정 기능을 찾기 어려웠다.

- 앱 달력의 일정 막대에서 해당 일정 편집기를 직접 연다. 날짜 숫자와 빈 공간은 날짜 선택을 유지한다. 위젯은 기존처럼 실제 누른 날짜를 연다.
- 날짜별 목록과 일정 탭에 **수정** 버튼을 표시한다. 일정 탭에도 원본 계정과 캘린더를 함께 표시한다.
- 기존 일정 편집 제목을 **일정 수정**, 저장 동작을 **변경사항 저장**으로 구분한다. 헤더와 저장 버튼은 스크롤 영역 밖에 두어 키보드 표시 중에도 접근할 수 있다.
- 편집 가능 여부를 목록과 편집기가 함께 판단한다. 반복·초대·할 일·권한 부족 항목은 **보기**로 안내하고 구체적인 사유를 상단에 표시한다. 기존 원본 일정 수정 제한을 유지한다.
- 기존 Provider UPDATE와 CalDAV 조건부 PUT을 그대로 사용한다. 원본 캘린더는 바꾸지 않으며 저장 실패 시 작성 내용과 기존 캐시를 유지한다.

## 검증

전용 API 35 에뮬레이터 `moa_calendar_api35`에서 임시 데이터로 검사했다. 네이버는 실제 저장소·Keystore·편집기를 사용하고 HTTPS 응답을 fixture interceptor로 제어했다. Google은 실제 Android Calendar Provider에 임시 캘린더를 생성해 검사했다.

| 검사 | 결과 |
| --- | --- |
| 단위 검사 | 90개 통과, 실패·오류·건너뜀 0 |
| lint | 오류 0, 기존 경고 36 |
| 앱·계측 APK | 빌드 성공 |
| Google·네이버 기존 일정 수정 | 제목·장소·메모 반영. 원본 계정·캘린더 유지, 총 일정 개수 변화 없음 |
| 수정 식별자 | Google Provider event ID 유지, 네이버 href·UID 유지 및 기존 ETag로 If-Match 요청 |
| 동기화 중 수정 | REPORT를 막아 둔 상태에서도 각각 2.5초 이내 저장 및 편집기 닫힘 |
| 취소·빈 제목 | 저장소 내용 변화 없음. 빈 제목은 안내 후 다시 입력 가능 |
| 네이버 서버 503 | 창과 작성 내용·기존 캐시 유지. 같은 창에서 재시도 성공 |
| 오래된 조회 결과 | 수정 이후 도착한 과거 REPORT가 수정 내용을 지우지 않음 |
| 홈 위젯 날짜 진입 | 최근 Activity 재사용·날짜 변경·동기화 중 재진입에서 캐시 유지, 자동 스피너 없음 |
| 기존 로그인·저장·삭제 회귀 | 초기 동기화, 재로그인, 재시도, 삭제 및 연결 해제 검사 통과 |
| 실제 앱 월 달력 막대 클릭 | 좌표 탭으로 해당 일정 수정 화면 열림 |
| 실제 앱 날짜별·일정 탭 수정 버튼 | 기존 내용이 채워진 편집기 열림 |
| 실제 앱 Google 저장 | 제목 수정 후 같은 Provider ID에 반영. 종일 종료일을 9/11에서 9/12로 변경하면 exclusive end가 9/13 00:00 UTC로 갱신됨 |
| 날짜 숫자 클릭 | 연결 막대가 있어도 숫자 12를 누르면 9/12와 해당 날짜 일정 표시 |
| 반복 일정 | 보기 버튼과 반복 일정 제한 안내, 저장 버튼 없음 |
| 100%·130% 글자와 키보드 | 실제 스크린샷 수동 검토. 고정 헤더·저장 버튼 유지, 나머지 필드는 스크롤 가능 |

네이버 클라우드의 실제 저장 응답과 Google 서버 업로드 성공을 확인했다는 의미는 아니다. Google 클라우드 반영은 기기 계정 동기화가 수행한다. Galaxy 실기기, 다른 Android 버전, 편집 중 화면 회전·프로세스 종료는 이번 검증 범위에 포함하지 않았다. 개발용 서명 APK이며 배포용 서명·스토어 출시는 수행하지 않았다.
