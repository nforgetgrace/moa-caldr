# v0.1.9 검증 · 2026-09-10

## 원인과 변경

실제 갤럭시에서 기존 일정이 보이는데 스피너가 오래 도는 현상을 조사했다. 설치된 APK가 저장소의 v0.1.8과 같은 파일임을 확인했다. Android 시스템 동기화는 없는 시점에도 앱의 네이버 요청은 실행 중이었고, Java 스레드 검사에서 `fetchTasks → fetchComponent → downloadResource`가 HTTP/2 응답 헤더를 기다리는 경로를 확인했다.

기존 캐시에는 ETag 없는 네이버 리소스가 다수 있었다. v0.1.8은 강한 ETag가 있는 캐시에서만 multiget을 사용했기 때문에, 서버가 calendar-query에 본문을 주지 않으면 많은 할 일 파일을 GET으로 하나씩 다시 가져왔다. HTTP 요청 하나의 제한 시간과 전체 조회 완료 시간은 달랐다.

- 초기 조회와 강한 ETag 없는 조회에서도 누락된 본문이 여러 개면 최대 50개씩 calendar-multiget으로 요청한다.
- 묶음 조회 미지원(400/403/405/501)은 전체 calendar-query로 한 번 복귀하고 이후 GET을 사용한다. 같은 미지원 묶음 조회를 재귀적으로 반복하지 않는다.
- 전체 href 집합·출처·상태·본문 검증과 기존 캐시 보존을 유지한다. multiget의 특정 본문만 없으면 기존처럼 GET으로 완성하고 GET 응답의 ETag를 사용한다.
- Google 상태는 콜백과 별도로 앱이 활성화된 동안 2초마다 재확인한다. 계정 없음·일시 정지에서는 조회를 중단하고, 취소된 조회가 이전 상태를 게시하지 않도록 한다. 이 확인은 서버 동기화를 요청하거나 달력 데이터를 다시 읽지 않는다.
- 실제로 활성인 동기화를 임의의 시간 경과만으로 완료 처리하지 않는다. 네이버 조회 기간, 할 일 범위, 동기화 주기, 기존 일정 표시는 유지한다.

Google 완료 알림 누락은 별도 회귀 검사로 방어한 경로이며, 이번 실기기의 주원인으로 확정한 것은 아니다. 실기기에서 직접 확인한 긴 작업은 네이버 할 일의 개별 GET 경로였다.

묶음 조회는 [RFC 4791 calendar-multiget](https://www.rfc-editor.org/rfc/rfc4791.html#section-7.9)의 기존 구현을 확대 적용했다. Google 상태는 기존 [Android isSyncActive](https://developer.android.com/reference/android/content/ContentResolver#isSyncActive(android.accounts.Account,%20java.lang.String)) 조회를 재사용한다. 의존성을 추가하지 않았다.

## 갤럭시 실기기

SM-F971N, Android 17/API 37에서 앱 APK만 v0.1.9(code 10)으로 업데이트했다. 기존 Google 선택과 네이버 계정을 유지한 상태에서 실제 네이버 서버가 multiget에 HTTP 207로 응답했고, 검증한 일정·할 일 캐시를 정상적으로 게시했다. 완료 후 접근성 트리에서 `동기화 중`이 사라지고 `일정 새로고침`이 표시됨을 확인했다.

첫 관측에서는 REPORT 응답이 시작된 13:44:19.811부터 캐시 게시 시각 13:44:34.772까지 약 15초였다. 이 구간의 REPORT는 query 4회와 multiget 50회였고, 배치 크기는 최대 50개였다. 탐색·앱 설치·실행 시간을 포함한 전체 사용자 대기 시간이나 모든 네트워크 환경의 성능을 보장하는 수치는 아니다. 이후에도 성공 응답과 갱신을 확인했으나, 앱 복귀와 재시도가 섞인 로그 구간을 단일 동기화 시간으로 취급하지 않았다.

REPORT 로그의 `headers_ms`는 응답 헤더 수신까지의 시간이며 전체 본문 다운로드·파싱 시간과 다르다. 원본 로그·화면·계정·일정 내용은 Git에서 제외한 로컬 진단 경로에만 두었다. 공개 기록에는 익명화한 상태와 측정 요약만 포함한다.

실제 서버는 이번 묶음 응답에서 비표준 형식의 ETag도 반환했다. 이 값을 유효한 강한 ETag로 간주해 본문 확인을 생략하지 않는다. 이 계정에서는 변경 없는 데이터도 묶음 조회할 수 있다. 실제 네이버/Google 일정 생성·수정의 클라우드 왕복과 다른 기기·계정은 이번 실기기 검사 범위에 포함하지 않는다.
