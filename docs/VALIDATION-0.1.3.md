# v0.1.3 검증 · 2026-09-09

## 수정 결과

- 서버 동기화 중에도 저장된 캘린더·일정·할 일을 읽을 수 있다. 원격 요청을 기다리며 `0개 캘린더`로 보이던 경로를 수정했다.
- 원격 변경은 기존 쓰기 잠금으로 직렬화하지만, 캐시 읽기는 네트워크 잠금을 기다리지 않는다. 일정·할 일·동기화 상태는 하나의 SharedPreferences 편집으로 반영하고, 독자는 `prefs.all`로 같은 저장 시점의 자료를 읽는다.
- 앱은 처음 저장된 자료를 표시한 뒤 서버를 조회한다. 초기 캐시를 아직 읽지 못한 상태를 미연결 상태로 표시하지 않는다. 실제 성공 응답으로 확인된 삭제/빈 자료는 계속 반영한다.
- 수동 새로고침만 상단 스피너를 표시한다. 앱 복귀·주기 갱신은 조용히 실행한다. 수동 표시 요청은 한 번만 소비하며, 취소된 이전 작업이 새 작업의 표시 상태를 덮지 않도록 구분한다.
- 최근 실행 앱에 남은 화면은 위젯 클릭 시 다시 만들지 않고 재사용한다. `singleTop`과 `onNewIntent`로 클릭한 날짜를 전달하고 캘린더 탭으로 이동한다. 같은 날짜를 다시 눌러도 요청을 처리하며, 설정·글자 크기 변경에 따른 화면 복원은 저장한 선택을 유지한다.
- 월간 위젯은 최대 3개 제목 뒤에 독립된 `+N` 줄을 표시한다. 총 5개면 제목 3개와 `+2`. 작은 위젯/큰 글자에서는 사용 가능한 공간에 맞게 제목 수를 줄이고 남은 개수를 유지한다.
- 위젯 좌우 여백 18→10dp, 위아래 16→8dp, 일정 글자 8→10sp. 일정이 있는 주에 필요한 공간을 배정하고 나머지를 분배한다.
- 앱 날짜 칸에도 최대 3개 제목과 `+N`을 표시한다. 빈 주의 높이는 줄이며 날짜 터치 영역은 최소 48dp를 유지한다. 하단 ‘일정 보기’ 링크로 전체 제목·시간·계정을 확인한다.
- 네이버 일정·할 일은 연보라 `#B39DDB`, Google 일정은 초록 `#03A86B`. 이전 캐시를 읽을 때도 색상을 적용하며, 다른 기기 캘린더는 원래 색상을 유지한다.

## 회귀 재현과 확인

사용자 화면에서 네이버가 연결되어 있는데도 앱에 잠시 0개 캘린더와 연결 안내가 나타나는 것을 확인했다. 이전 설명의 ‘Google 일시 조회 실패’는 가능성 중 하나였으며, 이번에는 네트워크와 캐시 읽기가 같은 잠금을 사용한다는 구체적인 원인을 재현했다.

기존 v0.1.2 APK에 테스트 전용 Instrumentation을 설치하고, 실제 저장소가 원격 요청에 사용하는 잠금을 유지했다. 저장된 일정 읽기가 **1.5초 제한을 넘겨 실패**했다. 수정본에서는 동일 조건에서 캐시 조회와 위젯 갱신이 완료됐다. 실제 서버 지연 대신 동일 잠금을 유지하는 결정적인 재현이며, 인증된 네이버 서버 왕복 테스트는 아니다.

테스트는 다음을 확인한다.

1. 원격 쓰기 잠금이 유지되어도 캐시의 캘린더와 일정이 읽히고 위젯 갱신이 끝난다.
2. 자동 동기화 중 앱을 열어도 일정이 보이고 수동 스피너는 없다.
3. 직접 새로고침하면 기존 일정은 남고 스피너만 나타난다.
4. 수동 새로고침이 끝난 뒤 홈 화면으로 나갔다 복귀하면 새 자동 갱신은 스피너 없이 실행된다.
5. 정상적으로 빈 캐시가 반영되면 삭제된 일정이 남지 않는다. ‘빈 결과는 무조건 이전 자료 유지’ 방식이 아니다.
6. 이전 초록색 네이버 캐시도 읽을 때 연보라로 바뀐다.
7. 실제 홈 화면 월간 위젯의 날짜를 눌러, 동기화 잠금 중에도 최근 앱의 Activity가 재생성되지 않고 일정이 보이는지 확인한다. 다른 날짜 재클릭과 앱 종료 후 위젯 재진입도 확인한다.

전용 AVD `moa_calendar_api35`, API 35, `emulator-5554`에서 실행했다. 테스트 도중의 스크린샷은 Instrumentation이 잠금을 유지하고 UI 검증을 끝낸 직후 캡처했다. 계정과 일정은 격리된 Provider/캐시 테스트 자료이며, 실제 사용자 자료가 아니다. 기본 및 130% 글자 크기의 앱·월간 위젯을 확인했다. 검증 후 테스트 자료와 테스트 APK를 제거하고 글자 크기를 원래 값으로 복원했다.

## 빌드와 증거

- JDK 21, SDK 37, Gradle 9.4.1.
- `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest` 성공.
- 단위 테스트 **60개 통과**, 실패·오류·건너뜀 0.
- Android lint **오류 0, 경고 27**. 남은 경고는 기존 버전/스타일·KTX·속성 호환 권고 등이다.
- 개발용 APK `dist/moa-calendar-0.1.3-debug.apk`, versionCode 4. APK 서명 검증 성공.
- 회귀 전후, UI 시나리오, 빌드·테스트·서명·해시 기록: `verification/v0.1.3/`.
- 화면: `screenshots/v0.1.3/`. 시각 검사는 실제 에뮬레이터 화면의 수동 검토이며 픽셀 일치를 주장하지 않는다.

격리된 에뮬레이터에서 회귀 검사 재실행:

```sh
adb -s DEVICE_SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
adb -s DEVICE_SERIAL install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s DEVICE_SERIAL shell am instrument -w com.moa.calendar.test/com.moa.calendar.RefreshRegressionRunner
# UI 시나리오는 -e scenario manual / background / widget를 추가한다.
# widget 시나리오는 에뮬레이터 홈 화면에 월간 위젯이 있어야 한다.
```

Instrumentation은 네이버 인증이 없는 전용 테스트 기기에서만 실행해야 한다. 임시 캐시를 사용한 뒤 원래 SharedPreferences를 복원한다. 앱 APK에는 테스트 자료나 테스트 실행기가 포함되지 않는다.

## 검증 한계

삼성 런처 실기기, 모든 위젯 크기·글자 크기, 실제 계정의 Google/Naver 클라우드 왕복은 이번 개발 환경에서 확인하지 않았다. 저장소 잠금 재현, 실제 앱 UI, 실제 홈 위젯, 100%/130% 글자 크기를 확인했다. 캘린더 서버가 실제 빈 결과를 전달하거나 기기 캘린더 권한/계정이 제거된 경우까지 이전 데이터를 무조건 유지하지는 않는다.
